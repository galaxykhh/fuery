```dart
// A Query<List<Todo>>, with no type arguments.
final todos = Query(
  queryKey: ['todos'],
  queryFn: (_) => api.getTodos(),
);

QueryBuilder(
  query: todos,
  builder: (context, state) => switch (state.data) {
    final data? => TodoList(data), // a List<Todo>
    null => const CircularProgressIndicator(),
  },
)
```

## Why Fuery

<CardGrid>
	<Card title="Built the Flutter way" icon="puzzle">
		A screen that shows a query stays a `StatelessWidget`. You define queries
		outside `build`, and widgets render them the way `StreamBuilder` renders a
		stream: builders for UI, listeners for side effects. Adopt it one screen at
		a time, with nothing to replace. For hooks,
		<a href="guides/hooks/">fuery_hooks</a> renders the same queries with
		`useQuery`, in a package of its own.
	</Card>
	<Card title="Nothing beyond Dart and Flutter" icon="code-branch">
		No code generation, no native code, and no platform setup. The core is pure
		Dart and depends only on the Dart team's `clock`, `collection`, and `meta`.
		Widgets, cubits, blocs, services, CLIs, and servers use the same query
		object.
	</Card>
	<Card title="Cached and fresh" icon="database">
		Every widget that uses a key shares one cache entry and one request. Stale
		data stays on screen while Fuery refetches it in the background. A refetch
		that returns the same items keeps the same objects, so list rows don't
		rebuild.
	</Card>
	<Card title="Types from your functions" icon="approve-check">
		Queries, mutations, and infinite queries take their types from their
		functions. Widgets, results, and callbacks carry those types without type
		arguments. Two cases name the type: a read or write by key alone, as in
		`getQueryData<List<Todo>>(['todos'])`, and an
		<a href="guides/infinite-queries/#cursor-based-pages">infinite query whose
		first page param is `null`</a>.
	</Card>
	<Card title="Built for real networks" icon="rocket">
		Failed fetches retry 3 times with backoff. Queries refetch when the app
		resumes and pause while the device is offline. Fuery cancels requests
		nobody needs anymore, without reporting them as errors. A query can poll
		until a condition holds, or fold a stream into the cache.
	</Card>
	<Card title="Persisted and inspectable" icon="magnifier">
		Queries you persist survive app restarts, with any key-value storage. The
		devtools show the cache inside the running app, on a device.
	</Card>
</CardGrid>

<p style="margin-top: 3rem;">
	<strong>Tested.</strong> Every package has 100% line coverage, and CI fails when a
	line loses it. The tests run on the oldest supported Flutter (3.27) and on the
	latest. The core's tests run under fake time. A regression suite keeps fixed edge
	cases fixed. Fuery cancels every timer on its destroy path and reads time from
	<code>package:clock</code>, so your own <code>fake_async</code> and widget tests
	don't leak timers. See <a href="guides/testing/">Testing</a>.
</p>
